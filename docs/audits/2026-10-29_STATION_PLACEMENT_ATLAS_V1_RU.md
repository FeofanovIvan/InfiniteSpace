# Контракт размещения сюжетных станций — MIKA World Atlas v1

Дата аудита: 29.10.2026.

**Первичный источник:** файл пользователя `MIKA_WORLD_ATLAS_V1(2).md` (28.10.2026), разделы `st_mw`, `st_lmc`, `st_smc`, `st_ngc6822`, `st_m31`, `st_m33`.

**Сверено с:** локальным полным проектом InfiniteSpace v34 — `scripts/AtlasSystem.gd`, `scripts/OtherSystem.gd`, `scripts/SolarSystem.gd`, `atlas/world_atlas.json`.

Все шесть станций вымышленные (`FICTION`), что соответствует авторскому каталогу.

## Другие объекты, которые нельзя смешивать с шестью сюжетными станциями

- Земля (стр. 51–56): ремонтная верфь и исследовательский город будущего — **планетная инфраструктура**, не тождественная `st_mw` у Каллисто.
- Венера (стр. 125–130): дрейфующая высотная исследовательская станция; **в атмосфере Венеры**, а не свободная станция где угодно.
- Уран (стр. 99–104): орбитальная антенна-колесо.
- Сатурн (стр. 85–90): брошенный пассажирский корабль в безопасной зоне на орбите.
- LMC, Вентра (стр. 226–239): верфь **на орбите третьей луны**, то есть спутника «Бриз», а не на орбите самой Вентры.
- M31, Гравис (стр. 469–480): сеть сооружений на орбитах нескольких лун.
- 4 художественных кольцевых оверлея `station_overlays` — **повторно используемые дополнительные визуальные элементы**, они не должны подменять объекты `st_*` или независимые космические локации.

## Найденные расхождения в Godot v34

1. `AtlasSystem.gd`: верфь Каллисто следует за луной со **статическим смещением `Vector2(78, -42)`** и вращением картинки. При этом по ТЗ нужна **орбитальная траектория вокруг Каллисто**; собственное вращение не заменяет орбиту.
2. `AtlasSystem.get_target_state("st_mw")` возвращает скорость `Vector2.ZERO` для перемещающейся вместе с Каллисто верфи. Для автопилота нужна мгновенная скорость цели, производная от движения Каллисто и локальной орбиты верфи.
3. `OtherSystem._station_world()` для пяти отдельных локаций повторно использует позицию третьей планеты (`_planets[2]`) плюс круговой сдвиг радиусом 240 единиц. **В источнике такой универсальной привязки нет**; для пяти станций нужны индивидуальные правила.
4. `OtherSystem.gd` рисует все пять сюжетных станций одной текстурой `res://assets/destinations/earth_station.png`. Это неверно для корабля, органической мегаструктуры, астероидного порта, пирамиды и ворот.
5. `OtherSystem.get_navigation_bodies()` ошибочно помечает любую внешнюю станцию как `EarthStation`. Нужно использовать настоящий `st_*` ID/название.
6. В `SolarSystem.gd` есть две самостоятельные визуальные станции у Земли: кольцо `AnchoredStation_Earth` и `EarthOrbitalStation_MIKO`. Пользователь ранее установил правило: возле Земли оставляем **одну** станцию. Требует отдельного устранения без разрушения `EarthStation` как навигационной цели.
7. В текущем `world_atlas.json` у станций сохранены `id`, имена и метка `fiction`, **но нет** полей `parent_body`, `orbit_radius`, `orbit_period`, `position_mode`. Их нужно добавить осмысленно, не выдумывая точных значений как факты из источника.

## Рекомендуемые действия

1. Ввести явный контракт `station_placement` с типом привязки (moon_orbit, free_drift, free_megastructure, artificial_asteroid, planet_orbit, gateway). Известные из документа связи заполнить; отсутствующие параметры обозначить как игровые решения, не как сведения из атласа.
2. Реализовать для Каллисто вложенные движения: Юпитер → Каллисто → орбита верфи, плюс собственное вращение верфи.
3. Для остальных пяти `st_*` сделать **разные модели и движения**, не вращать все одинаково вокруг третьей планеты.
4. Сохранить текущие кольцевые станции на выбранных обитаемых планетах как отдельную независимую подсистему.
5. Проверить в Godot F5 в шести системах; до этого не считать размещение исправленным.
