# MIKA — единый контракт комикса: Godot и печатный журнал

**Источник правил:** пользовательский `MIKA_Comic_Kit_Godot_v1.0_Integration_Module`, версия 1.0.
Комикс **не требует нового интерфейса MIKA**: каталог — отдельный Godot-модуль, его можно использовать позднее при создании эпизодов.

## 1. Неизменяемые ID

- **L01–L12 (12 надписей)**: L01 авторский caption; L02 речь; L03 фиолетовый информационный блок; L04 тревога; L05 радио; L06 шёпот; L07 мысли; L08 крик; L09 SFX; L10 заголовок; L11 время/место; L12 голос за кадром.
- **P01–P07 (7 композиций)**: P01 полный экран; P02 диагональный дуэт; P03 новости; P04 окно; P05 три полосы; P06 перекрывающиеся карточки; P07 персонаж за рамкой.
- **X01–X10 (10 переходов)**: X01 слайд; X02 диагональный; X03 разделение; X04 приближение; X05 match cut; X06 круг; X07 выход персонажа; X08 параллакс; X09 ударная тряска; X10 растворение.

**Не переопределять ID**: например, L03 всегда фирменный фиолетовый блок. Конфигурации берутся из `comic_element_catalog.json`, а не зашиваются отдельно в каждый эпизод.

## 2. Единые правила для видеокомикса в Godot

- Файлы модуля лежат в `res://mika_comic_kit/`; нельзя заменять основной `project.godot` игры.
- Выбор элементов по ID через `scripts/comic_factory.gd`.
- Рабочая ориентация горизонтальная. Компоновка изображения **COVER** с аккуратной обрезкой краёв без растягивания и чёрных полос.
- Текст — отдельный узел в экранных координатах поверх картинки, а не часть фона.
- У каждого кадра задавать `protected_zones` для лиц, глаз и значимых объектов; использовать `ComicLayout.locate`. Если фраза не помещается — делить или менять расположение кадра, не обрезать.
- Для P07 и X07 нужен **отдельный PNG с прозрачностью**; демонстрационный силуэт не подменяет Мику.
- Использовать `reduce_motion` при необходимости. Звуковых дорожек в поставленном модуле нет.

Сцены для проверки без вмешательства в основную игру:
- `res://mika_comic_kit/demo/CatalogDemo.tscn` — все 29 элементов.
- `res://mika_comic_kit/page01/Page01LibraryDemo.tscn` — исходная заставка 71 секунду.

## 3. Общий словарь стилей и выпуск PDF

- **Цвета C01–C12** и **шрифты F01–F04** определены в `data/comic_tokens.json`.
- Игровые и печатные элементы должны использовать одинаковые ID, содержание текста и цветовые токены.
- Источник данных страницы 01: 14 записей в `page01/page01_cues.json`, включая время, `style_id`, защищённые области.
- Печатное соответствие: `data/pdf_export_manifest_page01.json` с ключами `cue_id`/`style_id`.
- Исходник для печати: `page01/MIKA_Comic_Page_01_A4_300dpi.png`. **ВНИМАНИЕ:** название файла заявляет A4 300 dpi, но фактически изображение имеет **1447×2048 пикселей**, без метаданных DPI. При размещении на A4 это около **175 dpi**, не 300 dpi. Для качественной полиграфии потребуется настоящий оригинал 300 dpi; не увеличивать изображение автоматически и не считать существующий файл готовым к типографии.
- **Не делать скриншот Godot ради печати.** Брать оригинальное изображение, а речевые пузыри, таблички и подписи собирать векторными элементами в Scribus/Inkscape с сохранением ID/токенов.
- Переходы X01–X10 в PDF — **статичные композиции**, а не видео/анимации.
- Поля `pdf_panel_index` и `position_mm` в текущем манифесте **ещё не заполнены**. Редактор должен назначить расположение в печати; готового PDF-экспортера в поставленных файлах **нет**.

## 4. Правило работы над новой страницей

1. Выбрать исходную иллюстрацию высокого разрешения (отдельную от надписей).
2. Для каждой реплики зафиксировать `cue_id`, `text`, `speaker`, `style_id` (один из существующих L), защищённые области и время для экрана.
3. Для экранной композиции выбрать один P-ID и, при необходимости, переход X-ID. Не менять определения реестра.
4. Для печати добавить сопоставление `cue_id → style_id → pdf_panel_index → position_mm` в отдельный манифест страницы. До заполнения координат страница остаётся макетом.
5. Проверить, что надписи не задевают лица, не обрезаются на 16:9/21:9/4:3/20:9/16:10 и помещаются на A4 после ручной векторной вёрстки.
6. Для итоговой публикации нужны лицензированные шрифты и проверка качества PDF на печати. Шрифтовые файлы не прилагаются.

## 5. Архивная дисциплина

- Первоисточник Godot-модуля: `res://mika_comic_kit/`.
- Для редактора PDF отдельно устанавливается папка `InfiniteSpace_Comic_Print/source/` рядом с основным проектом.
- Отдельная папка печати — исходный **снимок** токенов/правил v1.0, не независимая альтернативная дизайн-система. Изменять определения ID отдельно в ней нельзя.
- При обновлении библиотеки синхронизировать соответствующие JSON обеих копий и обновить версию.
- Исходные изображения, оригинальная страница 01 и манифесты должны сохраняться без потери качества.
